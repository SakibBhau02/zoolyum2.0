## 1. Critical (P0) — এখনই ঠিক করা দরকার

### P0-1. Canonical URL ভুল ডোমেইনে — পুরো সাইট

Production-এ `https://zoolyum.com` → **308** → `https://www.zoolyum.com`।
কিন্তু প্রতিটি পেজের `<link rel="canonical">`, `og:url`, JSON-LD `url`/`@id`, sitemap — সবই `https://zoolyum.com` (non-www), অর্থাৎ **প্রতিটি canonical একটি redirecting URL**।

Evidence:
```
$ curl -I https://zoolyum.com/services/brand-strategy
HTTP/1.1 308 Permanent Redirect
Location: https://www.zoolyum.com/services/brand-strategy

$ curl -s https://www.zoolyum.com/services/brand-strategy | grep canonical
<link rel="canonical" href="https://zoolyum.com/services/brand-strategy"/>
```
Sitemap-এর ৩৫টি URL-ই non-www, তাই Googlebot/Bingbot প্রতিটি URL-এ দুবার হিট করছে (crawl budget নষ্ট), এবং GSC-তে "Duplicate, Google chose different canonical" আসবে।

**Cause:** `lib/data.ts:38`
```ts
export const SITE_URL = "https://zoolyum.com";
```
`app/layout.tsx:34` `metadataBase: new URL("https://zoolyum.com")` — আলাদা hardcode।

**Fix (একটা বেছে নিন, দুটো নয়):**
- (A) www-কে canonical রাখতে চাইলে → `SITE_URL = "https://www.zoolyum.com"`, `metadataBase`-ও `SITE_URL` থেকে নিন।
- (B) non-www canonical রাখতে চাইলে → Vercel-এ `zoolyum.com` primary domain করুন, `www` → `zoolyum.com` redirect।
- সব জায়গায় একটাই constant ব্যবহার করুন (`app/layout.tsx`, `lib/content.ts:440`, `app/sitemap.ts`, `app/robots.ts` — সবই `SITE_URL` ব্যবহার করে, শুধু `metadataBase` hardcoded)।

### P0-2. প্রতিটি inner page-এর OG image **404**

Service, case study, blog post — সব পেজের `og:image` ও `twitter:image` একটি URL দেখায় যেটি নেই:
```
$ curl -o /dev/null -w "%{http_code}" https://www.zoolyum.com/services/brand-strategy/opengraph-image
404
$ curl -o /dev/null -w "%{http_code}" https://www.zoolyum.com/blog/positioning-is-a-territory/opengraph-image
404
$ curl -o /dev/null -w "%{http_code}" https://www.zoolyum.com/work/apex-academy/opengraph-image
404
```
Local build-এও একই (reproducible, deploy-এর সমস্যা নয়)। Next 16 route টি generate করে **hashed** নামে:
```
/app/services/[slug]/opengraph-image-1m5q4s   ← 200 image/png
/services/brand-strategy/opengraph-image       ← 404
```
**অর্থ:** WhatsApp / LinkedIn / X / Facebook-এ কোনো service, case study বা blog post শেয়ার করলে **preview image আসবে না** — শুধু খালি কার্ড।

**Cause:** metadata-তে URL হাতে লেখা হয়েছে, Next-এর generated URL ব্যবহার হচ্ছে না:
- `app/(site)/services/[slug]/page.tsx:32,38`
- `app/(site)/blog/[slug]/page.tsx:45,51`
- `app/(site)/work/[slug]/page.tsx:36,42`

**Fix:** ওই `openGraph.images` / `twitter.images` override-গুলো মুছে দিন। রুটে `opengraph-image.tsx` ফাইল থাকলে Next নিজেই সঠিক hashed URL inject করে (`.../opengraph-image-1m5q4s?<hash>`)। `alt` ধরে রাখতে চাইলে `openGraph.images` না দিয়ে `openGraph`-এ শুধু `title/description/type` রাখুন।

### P0-3. Soft 404 — না-থাকা পেজ **HTTP 200** ফেরত দিচ্ছে

```
/blog/nonexistent-post         -> 200
/services/does-not-exist       -> 200
/work/nope                     -> 200
/totally-random-url            -> 404   (ঠিক আছে)
```
Content-টা 404 পেজের, কিন্তু status 200 → Google এটাকে **"Soft 404"** হিসেবে ধরে, এবং অসীম সংখ্যক ভুয়া URL (`/blog/feed.xml`, `/blog/rss.xml` — দুটোই ২০০!) index করার চেষ্টা করতে পারে। এটা crawl budget ও index quality দুটোই নষ্ট করে।

**Cause:** `app/loading.tsx` রুটে থাকায় পুরো tree একটি Suspense boundary-তে পড়ে, shell আগেই 200 দিয়ে flush হয়ে যায়; পরে `notFound()` throw হলে status বদলানো যায় না।

**Fix (একটি):**
1. `app/loading.tsx` সরান বা শুধু static রুটে scope করুন (dynamic `[slug]` route-এ নয়)। সরানোর পর যাচাই করুন: `curl -o /dev/null -w "%{http_code}" .../blog/nope` → `404` হওয়া চাই।
2. অথবা তিনটি `[slug]/page.tsx`-এ `export const dynamicParams = false;` — unknown slug routing-level-এই 404 হবে (তবে CMS থেকে নতুন slug deploy ছাড়া live হবে না)।

### P0-4. `sameAs` খালি — ব্র্যান্ড entity-র কোনো anchor নেই

Production JSON-LD:
```json
{ "@type": ["Organization","ProfessionalService"], "name":"Zoolyum",
  "sameAs": [] }
```
**Cause:** DB-তে `social.*` এখনও placeholder:
```
social.facebook  = "https://facebook.com"
social.instagram = "https://instagram.com"
social.linkedin  = "https://linkedin.com"
social.youtube   = "https://youtube.com"
```
`app/layout.tsx:72-82` ইচ্ছাকৃতভাবে pathname খালি হলে বাদ দেয় → ফলাফল খালি array।

দুইটা ক্ষতি:
1. **SEO/AEO:** Google Knowledge Graph ও AI answer engine ব্র্যান্ডকে চিনতে `sameAs` ব্যবহার করে। খালি থাকলে Zoolyum কোনো সোশ্যাল প্রোফাইলের সাথে যুক্ত হয় না।
2. **UX:** ফুটারের social icon গুলো `linkedin.com`, `facebook.com`-এর **হোমপেজে** নিয়ে যায়, Zoolyum প্রোফাইলে নয় (live HTML-এ যাচাই করা)।

**Fix:** Admin → Settings-এ আসল URL বসান:
- `https://www.linkedin.com/company/zoolyum/`
- `https://www.facebook.com/zoolyum/`
- Instagram/YouTube যদি না থাকে, সেটিং খালি রাখুন (placeholder নয়) — কোড খালি স্ট্রিং বাদ দেয়, কিন্তু `https://instagram.com` বাদ দেয় না।

### P0-5. চাকরিপ্রার্থীদের CV পাবলিক R2 bucket-এ

Candidate resume গুলো unauthenticated, publicly readable:
```
$ curl -I https://pub-8cb58c1039384eda970c22b3e0799ecb.r2.dev/uploads/...RESUME.pdf
HTTP/1.1 200
Content-Type: application/pdf
$ curl -r 0-100 ... -> 206
```
Bucket-এ `r2.dev` public URL enable করা আছে। URL জানলেই যে কেউ CV (নাম, ফোন, ঠিকানা, অভিজ্ঞতা) ডাউনলোড করতে পারে — কোনো auth নেই, কোনো expiry নেই। `noindex`-ও নেই।

**Fix:**
- R2 bucket-এ public access বন্ধ করুন; signed URL (৫–১৫ মিনিট expiry) দিয়ে admin-only download।
- অথবা CV গুলো private prefix-এ রাখুন এবং admin route দিয়ে proxy করুন।
- পুরোনো public object গুলো মুছে/rotate করুন (এগুলো ইতিমধ্যেই crawler-এ leaked হতে পারে)।

### P0-6. Security headers শূন্য

Production response-এ শুধু `Strict-Transport-Security` আছে (Vercel থেকে)। নেই:
`Content-Security-Policy`, `X-Frame-Options`/`frame-ancestors`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`।
`X-Powered-By: Next.js` ও leak হচ্ছে।

**Fix:** `next.config.ts`-এ `headers()` যোগ করুন (সাইটটি third-party script ব্যবহার করে — GA4, Clarity, Vercel Analytics — তাই CSP শুরু করুন `Content-Security-Policy-Report-Only` দিয়ে):
```ts
async headers() {
  return [{
    source: "/:path*",
    headers: [
      { key: "X-Content-Type-Options", value: "nosniff" },
      { key: "Referrer-Policy", value: "strict-origin-when-cross-origin" },
      { key: "X-Frame-Options", value: "SAMEORIGIN" },
      { key: "Permissions-Policy", value: "camera=(), microphone=(), geolocation=()" },
      { key: "Cross-Origin-Opener-Policy", value: "same-origin" },
    ],
  }];
}
```
সাথে `poweredByHeader: false`।

## 2. High (P1)

### P1-1. ফর্মে কোনো spam সুরক্ষা নেই + admin login-এ rate limit নেই
`app/admin/actions.ts:229-294` (`createLead`) — কোনো CAPTCHA, honeypot যাচাই, rate limit, বা payload size limit নেই। `_` দিয়ে শুরু হওয়া field শুধু **বাদ** দেওয়া হয়, reject করা হয় না (তাই honeypot কাজ করবে না)। `kind` ক্লায়েন্ট-নিয়ন্ত্রিত arbitrary string। প্রতি সাবমিশনে Meta CAPI + GA4 MP ফায়ার হয় → bot spam analytics-ও নষ্ট করবে।

`loginAction` (`:76-85`) — brute-force সুরক্ষা নেই; পাসওয়ার্ড শুধু env-এ একটা string, কোনো lockout/backoff নেই।

**Fix:** IP+email rate limit (Upstash/Vercel KV বা in-memory LRU), honeypot field থাকলে reject, submission size cap, এবং login-এ ৫ ব্যর্থ চেষ্টার পর backoff।

### P1-2. Site-wide color contrast fail (WCAG 1.4.3)
Axe চালানো হয়েছে ১৪টি পেজে — **প্রতিটিতেই** `color-contrast` (serious)। পরিমাপ করা মান:

| Element | Ratio | দরকার |
|---|---|---|
| Footer links (`text-ivory/45`) | 3.86 | 4.5 |
| Footer body (`#938b84` on `#2f2620`) | 4.41 | 4.5 |
| Careers meta (`text-ivory/40`, 11px) | 3.39 | 4.5 |
| Blog figcaption | 4.01 | 4.5 |
| Blog/story eyebrow (`text-ivory/40`) | 3.21 | 4.5 |

`text-ivory/40` → `text-ivory/60`, `text-ivory/45` → `/70` করলেই 대부분 পাশ করবে।

### P1-3. ফর্মের input-এ label নেই (WCAG 1.3.1/4.1.2 — **critical**)
Axe-এ `/careers`, `/resources`, `/newsletter`-এ `label` ও `select-name` **critical**:
- `/careers`: `input[type=text]`, `input[name=email]`, textarea, `select` — কোনোটিতেই label/aria-label নেই
- `/resources`: ৩টি gate email input (`email-brand-audit`, `email-content-calendar`, `email-campaign-brief`)
- `/newsletter`: `firstname`, `email` — placeholder `" "`, `id` নেই, `for` নেই

Visual floating-label আছে, কিন্তু DOM-এ সংযোগ নেই → screen reader শুধু "textbox" পড়ে। `id` + `<label htmlFor>` বা `aria-label` যোগ করুন।

### P1-4. Homepage title-এ ব্র্যান্ড দুইবার

## 6. "ChatGPT / Gemini / Claude আমাকে খুঁজে পাবে?" — প্রমাণভিত্তিক উত্তর

### যা AI-কে ব্র্যান্ড চিনতে বাধা দিচ্ছে ❌
1. **`sameAs: []`** — Google Knowledge Graph-এ ব্র্যান্ড-প্রোফাইল লিংকের একমাত্র মেশিন-রিডেবল সিগন্যাল। এটা খালি মানে "এই ব্র্যান্ড কোন সোশ্যাল/এন্টিটি সেটের" — মডেলের কাছে প্রমাণ নেই।
2. **Wikidata/Wikipedia-তে কোনো entity নেই** — যাচাই করা:
   `wbsearchentities&search=Zoolyum` → `{"search":[]}`, Wikipedia `totalhits: 0`.
   LLM-এর প্রশিক্ষণ ডেটায় ব্র্যান্ডটি structured entity হিসেবে নেই; শুধু Facebook (757 likes) + LinkedIn (123 followers) + CB Insights page আছে।
3. **Hero-তে entity-defining বাক্য নেই** — H1/sub-headline-এ "Zoolyum", "Dhaka", "brand strategy agency" একসাথে নেই। Answer engine প্রথম ২ লাইন থেকেই entity+service+location টেনে নেয়।
4. **OG image 404** — LinkedIn/X-এ শেয়ার হলে ভিজুয়াল প্রুফ তৈরি হয় না, ফলে সোশ্যাল সিগন্যালও কম।
5. **Canonical দ্বন্দ্ব** — AI crawler non-www canonical দেখে redirect অনুসরণ করে; একাধিক URL-এ একই কনটেন্ট থাকায় source attribution দুর্বল হয়।
